# 0009. 새 시뮬레이션의 화면 글자는 `_en` 파일에 한국어로 쓴다

## 맥락

새 시뮬레이션은 한국어 하나로만 낸다. chipper는 영어(`en`)를 기본 언어로 고정하고, `<id>-strings_en.json`이 모든 글자 키를 정의해야 빌드한다. 또 `babel/<id>/<id>-strings_ko.json`이 있어야만 `ko`를 실제 언어로 인정하고, 없으면 `--locales=ko`로 빌드해도 조용히 `en`으로 빌드된 뒤 시작하자마자 `localeToLocalizedName` 오류로 멈춘다.

## 결정

화면 글자는 `<id>-strings_en.json` 한 파일에 한국어로 직접 쓴다. 빌드할 때만 같은 파일을 슬롯의 `babel/<id>/<id>-strings_ko.json`으로 복사하고 빌드 뒤 지운다. 시뮬레이션 폴더에 `<id>-strings_ko.json`이 따로 있으면 그것을 대신 쓴다.

## 버린 대안

- **영어 원문 + 한국어 번역 파일 두 벌**: 영어판을 낼 계획이 없는데 키마다 두 언어를 맞춰야 한다. 한쪽만 고치는 실수가 생긴다.
- **babel 저장소에 번역 추가 커밋**: babel은 고정된 PhET 저장소라 우리 커밋을 섞을 수 없다.

## 결과

- 파일 이름(`_en`)과 내용(한국어)이 다르다. 영어 단어만 든 값이 있으면 테스트가 실패한다.
- 이름이 babel에 이미 있는 폴더와 겹치면 빌드 도구가 거부한다. 새 id는 PhET 저장소 이름과 겹치지 않아야 한다.
- 나중에 영어판을 내려면 `<id>-strings_ko.json`을 따로 두고 `_en`을 영어로 바꾸는 길이 열려 있다.
