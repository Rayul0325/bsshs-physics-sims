# 0008. 새 시뮬레이션은 PhET MIT 부품의 고정 묶음 하나로 만든다

## 맥락

기말 핵심 주제(광전 효과, 콤프턴 산란, 레이저, 반도체·다이오드, 편광)는 PhET HTML5 시뮬레이션에 없다. 새로 만들어야 하는데, 63개와 같은 조작감·디자인·학교 표기·서랍을 가져야 하고 정밀도는 PhET 수준이어야 했다.

## 결정

PhET가 공개한 MIT 부품(scenery, sun, joist, axon, dot, kite, phet-core, scenery-phet, tandem, bamboo 등)과 chipper로 TypeScript 시뮬레이션을 만든다. 부품은 63개의 고정 부품 묶음 가운데 가장 최근 것 하나(`newSimBase`: energy-skate-park-basics 1.5.0의 묶음, chipper 2.0.0, Node 24)로 고정한다. 묶음의 나이는 핵심 부품 9개가 main에서 갈라진 날짜 중 가장 오래된 날짜로 판단한다. 63개와 같은 패치(학교 표기, 외부 통신 끄기, 토큰, 공통 부품 용어 교정)를 적용한다.

## 버린 대안

- **일반 웹 기술(Canvas, 차트 라이브러리)로 따로 만들기**: 패널·슬라이더·메뉴줄·About 창·시작 화면을 63개와 맞추는 비용이 크고, 토큰 패치가 적용되지 않아 디자인 값을 따로 관리해야 한다.
- **PhET 옛 Java 시뮬레이션을 옮기기**: 그림·배치·소스를 베끼는 것은 하지 않기로 했다(독자 설계).
- **부품을 main 최신으로**: 공개 저장소가 닫혀 최신도 고정이고, 63개 중 실제로 빌드에 성공한 묶음을 써야 빌드가 보장된다.
- **유지보수 커밋 날짜로 묶음 고르기**: 유지보수 패치는 옛 부품 위에 얹혀 날짜만 최근이다. 갈라진 날짜를 써야 실제 부품 나이를 안다.

## 결과

- 새 시뮬레이션은 그 묶음의 API에 묶인다. 다른 부품 버전의 예제 코드는 그대로 쓸 수 없다.
- `phet.phetLibs`에는 묶음에 있는 저장소만 쓸 수 있다.
- chipper가 이 브랜드에서 타입 검사를 건너뛰어 빌드 도구가 `tsc -b`를 따로 돌린다. chipper의 글자 수집 방식 때문에 문자열 참조를 별명으로 쓸 수 없다.
- 결과물은 63개와 같은 폴더, 같은 검사(V1, V2, V9, V10)를 거친다.
