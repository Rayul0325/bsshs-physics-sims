# 0006. 선생님 재확인은 물리 내용이 바뀔 때만 한다

## 맥락

확인 담당 선생님이 14개 서랍 내용을 승인하면 「선생님 확인 완료」를 보여 준다. 승인 뒤 내용이 바뀌었는데 표시가 남으면 승인받지 않은 내용이 승인된 것처럼 보인다. 반대로 디자인·글꼴·용어 교정 같은 변경마다 승인이 풀리면 선생님에게 같은 내용을 반복해 부탁해야 한다.

## 결정

승인할 때 물리 내용 해시를 함께 기록하고, 사이트를 만들 때 현재 해시와 다르면 「선생님 확인 중」으로 보인다. 해시에는 수업 내용 파일, 측정 항목 정의·그래프(`drawer.json`), 물리 검사 사례(`cases.json`), 값을 읽고 계산하는 어댑터 코드(`adapter.mjs`), 새 시뮬레이션의 모델 코드(`js/model/**`)만 넣는다. 디자인 토큰, 테마, 학교 표기, 용어 교정, 서랍 코드, 보기 코드는 넣지 않는다. JSON은 정규화해서 해시한다.

## 버린 대안

- **모든 변경에 재확인(빌드 결과 전체 해시)**: 토큰·글꼴만 바꿔도 14개 승인이 모두 풀린다.
- **사람이 직접 상태를 되돌리기**: 바뀐 것을 잊으면 승인받지 않은 내용이 「확인 완료」로 공개된다.
- **어댑터 코드를 해시에서 빼기**: 고치기는 쉽지만 어댑터는 자속 변화율, 굴절각, 블로흐 벡터처럼 학생이 보는 값을 직접 계산한다. 계산이 바뀌어도 V3 사례가 그 값을 덮지 않으면 「확인 완료」가 그대로 남는다.

## 결과

- 어댑터를 조금만 고쳐도(주석 포함) 그 시뮬레이션은 재확인을 받아야 한다. 승인 뒤에는 어댑터를 꼭 필요할 때만 고친다.
- 새 시뮬레이션의 보기 코드 안에 물리 계산을 두면 해시가 그 변경을 놓친다. 물리는 `js/model/`에 둬야 한다.
- 해시 범위를 바꾸면 범위 버전을 올려 모든 승인을 한꺼번에 무효로 한다.
- 상태는 빌드 때 HTML에 박히므로 상태 파일이나 내용을 바꾼 뒤 사이트를 다시 만들어야 한다.
