# 0002. 번역 저장소는 릴리스 시각 직전 커밋으로 고정한다

## 맥락

시뮬레이션의 `dependencies.json`은 형제 저장소 SHA를 모두 고정하지만 번역 저장소 `babel`만은 고정하지 않는다. PhET 빌드 서버는 빌드하는 순간의 `babel` main을 썼다. 그대로 두면 같은 시뮬레이션을 빌드해도 날마다 한국어 문자열이 달라지고, 용어 교정 목록이 맞지 않게 될 수 있다.

## 결정

시뮬레이션마다 `dependencies.json` 주석에 적힌 릴리스 시각 직전의 `babel` main 커밋을 골라 매니페스트의 `babelSha`에 고정한다. 새 시뮬레이션은 `newSimBase` 묶음의 `babelSha`를 쓴다.

## 버린 대안

- **빌드할 때의 `babel` main**: 결과가 재현되지 않고, 번역이 바뀌면 용어 교정(필수 규칙)이 조용히 어긋나거나 빌드가 실패한다.
- **모든 시뮬레이션에 같은 `babel` 커밋 하나**: 옛 시뮬레이션의 문자열 키와 새 번역 파일의 키 구조가 달라 일부가 빠지거나 바뀐다. PhET가 실제로 내보낸 번역과도 멀어진다.

## 결과

- 같은 소스면 같은 한국어 문자열이 나온다. 용어 교정과 제목(`data/titles.json`) 검사는 이 고정된 표를 기준으로 한다.
- 2026-10-09 이후 `babel`에 들어온 번역 개선은 반영되지 않는다. 번역이 없는 문자열(일부 화면 낭독용 공통 문자열)은 영어로 남는다.
