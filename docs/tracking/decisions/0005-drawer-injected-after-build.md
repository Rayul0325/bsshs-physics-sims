# 0005. 수업 서랍은 빌드가 끝난 HTML에 독립 화면 요소로 넣는다

## 맥락

시험 범위 14개(PhET 9개 + 새 5개)에 측정 기록, 그래프, 공식·용어 서랍을 붙여야 했다. 그런데 PhET 9개는 공통 부품(scenery, sun, joist) 버전이 시뮬레이션마다 달라 한 부품을 모두에 끼워 넣을 수 없다. 또 서랍을 닫았을 때 실험 화면이 원본 배치와 픽셀까지 같아야 하고, PhET 물리 계산과 시뮬레이션 코드는 고치지 않아야 한다.

## 결정

서랍은 PhET 그리기 라이브러리 밖의 일반 DOM(shadow DOM) 화면 요소다. 빌드가 끝난 단일 HTML의 `</body>` 바로 앞에 토큰 CSS, 서랍 데이터, 서랍 코드, 시뮬레이션별 어댑터를 인라인으로 넣는다. 어댑터는 실행 중 `phet.joist.sim.screens[i].model`의 Property를 읽기만 하고, 자동 물리 검사용 `apply`만 모델 입력을 바꾼다.

## 버린 대안

- **PhET scenery 부품으로 서랍 만들기**: 시뮬레이션마다 scenery·sun 버전이 달라 하나의 구현이 모든 버전에서 돌지 않는다. 버전별로 따로 쓰면 14개를 각각 유지해야 한다.
- **시뮬레이션 소스에 측정 코드를 패치로 넣기**: 패치가 시뮬레이션 저장소와 모델 파일을 건드리게 되어 「패치는 공통 부품의 테마·브랜드·문자열·외부 통신만」이라는 경계를 깬다.
- **실험 화면 옆에 서랍 자리를 만들어 화면을 밀기**: 실험 화면 배치가 바뀐다.

## 결과

- 서랍은 63개·5개 빌드와 상관없이 한 벌의 코드다. 빌드를 다시 하지 않고 주입만 다시 할 수 있다.
- 어댑터는 시뮬레이션 버전의 모델 속성 이름에 묶인다. PhET 버전을 바꾸면 어댑터를 다시 맞춰야 한다.
- 어댑터는 HTML에 인라인되므로 `import`를 쓸 수 없다.
- 서랍이 시뮬레이션 위에 덮이므로 이벤트 차단(scenery가 `window`에서 입력을 받음)과 휴대폰 시트 높이 계산이 필요하다.
- V9 배치 비교의 기준은 서랍 없는 학교판 빌드이고, 열기 버튼 상자만 비교에서 뺀다.
