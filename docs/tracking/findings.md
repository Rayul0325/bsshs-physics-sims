# 풀지 못한 문제와 받아들인 한계


## 받아들인 한계

### 화면 낭독기 전용 공통 문자열이 영어

- **보이는 것**: 시뮬레이션을 `?supportsInteractiveDescription=true`로 열면 「Reset All」 같은 공통 부품의 화면 낭독용 이름이 영어로 나온다. PhET 빌드 63개와 새 시뮬레이션 5개에서 모두 같다. 기본 설정에서는 노출되지 않는다.
- **영향**: 화면 낭독기를 켠 학생만 일부 영어를 듣는다. 화면 글자에는 영향이 없다.
- **지금 못 푸는 이유**: 고정된 번역 저장소(`babel`)에 그 문자열의 한국어가 없다. 용어 교정은 기존 번역의 오역을 고치는 규칙이라, 번역이 없는 문자열을 새로 채우는 것은 범위 밖이다.
- **접근**: 공통 부품 문자열의 한국어 번역을 새로 더하는 규칙 종류를 만들고 패치 허용 목록에 babel 공통 부품 한국어 파일을 넣을지 결정해야 한다.

### 패러데이 법칙의 기전력 부호 규약

- **보이는 것**: faradays-law 서랍의 기전력은 ε = +N ΔΦ/Δt 부호로 나온다(수업 식 ε = −N ΔΦ/Δt와 크기는 같고 부호 규약이 반대). 감은 수도 그림 고리 수의 절반(아래 코일 2, 위 코일 1)이다.
- **영향**: 학생이 부호만 보고 렌츠 법칙을 확인하면 반대로 읽을 수 있다.
- **지금 못 푸는 이유**: PhET 물리 계산은 고치지 않는다. 어댑터에서 부호를 뒤집으면 PhET 화면(전구·전압계)과 서랍 값이 어긋난다.
- **처리**: 수업 내용 파일의 패러데이 법칙 공식에 「참고」로 규약 차이를 적었다.

### 파동 간섭의 격자 오차

- **보이는 것**: wave-interference의 무늬 간격이 작은 각 근사 Lλ/d보다 5% 이상 크고, 정확한 기하로 계산한 값과도 수 % 어긋난다(간섭 화면은 점파원 간격 반올림으로 조금 더 큼).
- **영향**: 학생이 Lλ/d로 바로 계산해 비교하면 8~20% 차이가 난다.
- **지금 못 푸는 이유**: PhET가 격자 위에서 파동 방정식을 푸는 방식에서 나오는 차이다. PhET 계산은 고치지 않는다.
- **처리**: V3 기대값을 정확한 기하로 계산하고 허용 오차 4%를 사례에 적었다. 공식 칸에 「참고」로 근사 차이를 적었다.

### 반도체 리플 전압은 6% 허용 오차로 비교

- **보이는 것**: bsshs-semiconductor 평활 축전기 리플 사례 두 개(반파, 브리지)만 허용 오차가 6%다.
- **영향**: 리플 값은 근사식과 6% 안으로 맞는다는 것까지만 확인된 상태다.
- **지금 못 푸는 이유**: 비교 기준이 수업 근사식 ΔV ≈ V_p/(fRC)(브리지는 V_p/(2fRC))이고, 근사식 자체가 실제 방전 곡선과 몇 % 다르다. 기준을 바꾸면 사례가 바뀌어 물리 내용 해시도 바뀐다.
- **접근**: 선생님 확인 때 근사식 비교로 충분한지 함께 확인한다.

### 「부산과학고」 워드마크와 한글의 글꼴

- **보이는 것**: 메뉴줄 워드마크 PNG는 **빌드한 컴퓨터**의 한글 글꼴로 그려진다. 시작 화면 SVG의 워드마크, 목록 사이트와 서랍의 한글은 **보는 기기**의 한글 글꼴로 그려진다. 한글 웹 글꼴은 넣지 않았다.
- **영향**: 기기마다 한글 모양이 조금씩 다르다. 다른 컴퓨터에서 다시 빌드하면 워드마크 PNG 바이트가 달라져 배포 결과가 바이트 단위로 재현되지 않는다(검사는 통과).
- **지금 못 푸는 이유**: 한글 웹 글꼴은 파일이 커서 68개 HTML마다 넣으면 시뮬레이션 크기가 크게 는다. 기기 글꼴 목록은 토큰의 `font.koreanFallback`에 둔 바꿔도 되는 기본값이다.
- **접근**: 「부산과학고」 다섯 글자만 담은 부분 글꼴을 만들어 워드마크 렌더와 시작 화면에 쓰는 방법.

### 메뉴줄 배경은 PhET 흰색·검정

- **보이는 것**: 시뮬레이션 아래 메뉴줄 배경은 토큰 색이 아니라 PhET 흰색(홈 화면은 검정)이다. 글자색만 토큰을 따른다.
- **영향**: 메뉴줄이 학교 디자인과 조금 어긋나 보인다.
- **지금 못 푸는 이유**: joist가 메뉴줄 색을 `'white'`/`'black'` 글자와 직접 비교해 글자색·로고를 고른다. 다른 색을 주면 로고·글자 선택이 깨진다. joist 비교 코드를 고치는 규칙은 63개 버전마다 모양이 달라 위험이 크다.

## 풀지 못한 문제

### 수업 내용 테스트에 나머지 54개 id가 직접 적혀 있음

- **보이는 것**: `tests/data/lessons.test.mjs`는 시험 범위 id를 `data/exam-scope.json`에서 읽지만, 시험 범위 밖 54개 id(`OTHER_IDS`)와 전체 수 68은 코드에 적혀 있다. 변형 시뮬레이션을 시험 범위로 옮기거나 빼면, 또는 새 시뮬레이션을 하나 더하면 「units.json covers all 68 ids exactly once」 테스트가 실패한다.
- **영향**: 시험 범위 교체가 `data/exam-scope.json` 한 파일로 끝나지 않는다. 테스트 목록을 같이 고쳐야 한다(데이터가 틀리는 것은 아니고, 실수로 목록을 안 고치면 검증이 실패할 뿐이다).
- **지금 못 푸는 이유**: 테스트 코드 변경이 필요하다. 54개 목록은 「시험 범위 밖 시뮬레이션이 정확히 무엇인가」를 따로 고정하는 역할도 하고 있어서, 데이터에서 계산하면 그 교차 확인이 사라진다. 어느 쪽을 택할지 정해지지 않았다.
- **접근**: 나머지 목록을 `data/sims.json` + `sims/` 폴더 − 시험 범위로 계산하고, 68은 그 합으로 바꾼다. 고정 확인이 필요하면 `data/sims.json`의 63개 수만 따로 고정한다.

### 서랍이 빠진 시뮬레이션의 카드에 확인 배지가 남음

- **보이는 것**: 시험 범위 PhET 시뮬레이션이 물리 검사(V3)에 실패하면 verify가 그 시뮬레이션을 서랍 없이 공개한다. 그런데 목록 사이트 카드에는 「시험 범위」 표시와 「선생님 확인 중」 같은 확인 상태 배지가 그대로 붙는다.
- **영향**: 학생은 카드에서 서랍(측정 기록·공식)이 있는 것으로 기대하지만 열면 서랍이 없다. 확인 대상인 서랍 내용이 공개되지 않았는데 확인 상태가 보인다.
- **지금 못 푸는 이유**: 학생에게 무엇을 보여 줄지(배지를 숨길지, 「수업 서랍 준비 중」 같은 표시를 둘지, 시험 범위 칸에 계속 둘지) 디자인 결정이 필요하다.
- **접근**: 사이트 생성기가 `--no-drawer`로 받은 id를 카드 모델에 넘겨 배지·표시를 바꾸게 하고, 사이트 테스트에 그 경우를 더한다.

### 확인 기록 도구가 상태 전이 순서를 강제하지 않음

- **보이는 것**: `npm run approve -- <id>`는 `수정 중`인 시뮬레이션도 바로 `확인 완료`로 쓴다. `set-status`는 `확인 완료`에서 바로 `확인 중`으로도 바꾼다.
- **영향**: 정해 둔 흐름(오류 지적 → 고침 → `확인 중`으로 다시 공개 → 승인)을 건너뛴 기록이 남을 수 있다. 다만 승인은 언제나 그 순간의 물리 내용 해시를 기록하므로, 승인받지 않은 내용이 「확인 완료」로 보이는 일은 없다.
- **지금 못 푸는 이유**: 관리자가 직접 쓰는 도구라 순서를 강제할지 정해지지 않았다(선생님이 고친 내용을 그 자리에서 바로 승인하는 경우를 허용할지).
- **접근**: `approve`를 `수정 중`에서 부르면 경고하거나 별도 플래그를 요구하게 한다.

### 설정 창·키보드 도움말 창은 자동 검사되지 않음

- **보이는 것**: `check-sim`의 「PhET」 이름 검사는 시작 화면, 메뉴, About 창에서만 돈다. 설정 창과 키보드 도움말 창은 열지 않는다.
- **영향**: PhET 버전이 바뀌거나 새 규칙이 문자열을 바꿨을 때 두 창에 「PhET」가 새로 생겨도 자동으로 잡지 못한다.
- **지금 못 푸는 이유**: 두 창을 여는 방법이 joist 세대마다 달라 63개 버전 모두에서 안정적으로 여는 코드가 아직 없다. 지금은 63개 빌드의 문자열 표 전체를 훑는 점검으로 대신했다.
- **접근**: 검사기에 joist 세대별 설정 창 열기 단계를 더하고 같은 `phetName` 훑기를 돌린다.

### 수소 원자 모형의 수업 내용은 대부분 표준 공식

- **보이는 것**: `data/lessons/models-of-the-hydrogen-atom.json`의 공식 대부분(보어 궤도 반지름, 뤼드베리 식, 드브로이 정상파 조건, 선 스펙트럼)의 원천이 「표준」이다. 수업 기록에 이 부분이 적다.
- **영향**: 시험 범위와 맞지 않는 공식이 「공식·용어」 탭에 있을 수 있다.
- **지금 못 푸는 이유**: 수업 기록에 근거가 없고, 판단할 사람은 확인 담당 선생님이다.
- **접근**: 선생님 확인 때 이 시뮬레이션의 범위를 따로 물어 「참고 · 시험 범위 아님」 표시를 조정한다(물리 내용 해시가 바뀌므로 그 뒤 다시 승인받는다).

### 없는 주소가 404 대신 목록 페이지를 200으로 돌려줌

- **보이는 것**: `https://bsshs-physics-sims.pages.dev/<없는 경로>`(오타 난 시뮬레이션 주소 포함)가 200과 목록 페이지 내용을 돌려준다. `dist/`에 `404.html`이 없어 Cloudflare Pages가 단일 페이지 앱처럼 처리하기 때문이다(2026-11-04 확인).
- **영향**: 학생이 잘못된 링크를 열면 오류 대신 목록이 보인다(큰 문제는 아님). 더 중요한 것은 배포 확인에서 상태 코드 200만 보면 빠진 시뮬레이션을 놓친다는 점이다. 지금 배포 확인 절차는 `dist/`와 바이트 비교를 하므로 막혀 있다.
- **지금 못 푸는 이유**: 사이트 생성기(`site/build-site.mjs`)를 고쳐야 하는 코드 변경이다.
- **접근**: 사이트 생성기가 `404.html`(「없는 페이지」 안내 + 목록 링크, 토큰 디자인)을 함께 만들게 하고, 사이트 테스트에 그 파일을 더한다.

## 측정 항목을 바꾸고 정의 버전을 올리지 않으면 옛 기록과 섞임

- **무엇이 보이나**: `drawer.json`의 측정 항목을 바꾸고 `schemaVersion`을 그대로 두면, 같은 저장 키에 옛 줄과 새 줄이 한 표로 쌓인다.
- **영향**: 이미 기록을 가진 학생 브라우저의 표와 그래프 값이 어긋난다.
- **지금 못 푸는 이유**: 지금은 항목을 바꿀 계획이 없고, 저장 형식에 항목 지문을 더하면 배포된 기록과의 호환 처리까지 함께 설계해야 한다.
- **접근 방법**: 키·단위·수업 단위의 지문을 기록과 함께 저장하고 다르면 옛 기록으로 처리하거나, (id, `schemaVersion`)별 지문을 고정하는 테스트를 둔다.

## 시뮬레이션 준비 판정 코드가 다섯 곳에 복사되어 있음

- **무엇이 보이나**: `drawer/runtime.js`, `site/build-site.mjs`, `tools/check-sim.mjs`, `tools/compare-layout.mjs`, `adapters/faradays-electromagnetic-lab/adapter.mjs`에 같은 판정이 따로 있다.
- **영향**: 새 joist 세대에 맞춰 한 곳만 고치면 썸네일이나 배치 비교가 다른 조건으로 기다린다.
- **지금 못 푸는 이유**: 다섯 곳의 실행 환경(시뮬레이션 페이지 안, Playwright 평가, 인라인 어댑터)이 달라 한 파일로 합치려면 주입 방식을 다시 정해야 하고, 지금 값은 모두 같다.
- **접근 방법**: 판정 함수 문자열 하나를 `drawer/`에 두고 각 도구가 읽어 평가한다.
