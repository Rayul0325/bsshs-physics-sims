# 보안·개인정보 정책

공개 정적 사이트라 인증과 권한이 없다. 지켜야 할 것은 세 가지다: 개인정보가 공개되지 않을 것, 학생 기기에서 밖으로 나가는 통신이 없을 것, 저장소에 비밀 값이 없을 것. 여기에 배포·공개에 쓰는 관리자 자격 증명의 관리가 더해진다.

## 지키는 자산

| 자산 | 어디에 있나 | 공개되면 안 되는 이유 |
|---|---|---|
| 선생님 실명, 학생 이름, 개인 메일 | 저장소 밖 실명 목록 `~/.config/bsshs-physics-sims/private-names.txt`(검사용), 비공개 저장소의 커밋 메타데이터 | 학교 공식 자료가 아닌 학생 제작물에 실명을 걸 수 없다 |
| 수업 녹음 원본과 전사, 수업 발언 직접 인용 | 저장소 밖 수업 기록 보관소(읽기 전용) | 수업 내용의 원문 공개는 허락받지 않았다 |
| 비공개 저장소의 git 기록 | 이 저장소가 들어 있는 비공개 저장소 | 다른 과제, 실명 작성자, 로컬 작업 문서가 섞여 있다 |
| 학생의 측정 기록 | 각 학생 브라우저의 `localStorage` | 기기 밖으로 보낼 이유가 없고, 보내는 길도 두지 않는다 |
| Cloudflare 계정 토큰 | wrangler가 사용자 설정 폴더에 저장(저장소 밖) | 사이트를 바꾸거나 지울 수 있다 |
| GitHub push 권한 | 관리자 컴퓨터의 git 자격 증명(저장소 밖) | 공개 저장소를 바꿀 수 있다 |

## 누가 무엇을 할 수 있나

| 주체 | 할 수 있는 일 | 할 수 없는 일 |
|---|---|---|
| 학생·선생님(방문자) | 링크로 사이트 열기, 서랍 기록·CSV·PNG 내려받기(자기 브라우저 안) | 다른 사람 기록 보기, 무엇이든 서버에 저장, 로그인(없음) |
| 확인 담당 선생님 | 내용을 검토하고 승인·오류 지적을 관리자에게 전함 | 상태 파일을 직접 고치기(시스템 접근 없음). 화면이나 저장소에 이름이 남는 일 |
| 관리자(학생 제작자) | 빌드, 검증, 확인 상태 기록(`approve`, `set-status`), Cloudflare 배포, 공개 저장소 push | 상태 파일을 손으로 고치기, 검증을 통과하지 않은 `dist/` 배포, 이 저장소의 기록을 공개 저장소에 push, 실명 목록을 저장소에 넣기 |
| 코딩 에이전트 | 코드·문서 수정, 빌드·검증 실행 | 관리자의 확인 없이 공개 저장소 push나 배포, 실명 목록 내용을 출력·인용 |

## 개인정보 규칙

- 실명 목록은 저장소 밖 파일에만 둔다. 검사 도구는 이 파일을 읽어 **파일 이름과 건수만** 보고한다. 이름 자체, 일치한 줄 번호, 앞뒤 문맥을 화면·보고서·로그·문서에 쓰지 않는다. 같은 목록으로 돌렸는지는 목록 지문(해시 앞 12자리)으로만 비교한다.
- 실명 검색 대상: 빌드된 68개 HTML, `dist/` 아래 모든 파일(썸네일 포함), `git ls-files`의 모든 파일. 한 이름을 UTF-8(NFC·NFD), 자바스크립트 `\uXXXX`, HTML 숫자 문자 참조 모양으로 모두 찾는다. 공개 직전에는 내보내기 폴더도 같은 기준으로 검사한다. 0건이 아니면 공개·배포하지 않는다.
- 이 검사는 목록에 적힌 글자 그대로만 찾는다. 띄어쓰기를 바꾼 모양, 이미지 속 글자, 목록에 없는 이름은 잡지 못한다. 그래서 수업 내용을 쓸 때부터 실명과 인용을 넣지 않는다.
- 수업 내용 파일(`data/lessons/*.json`)의 `sources`에는 녹음 식별자(날짜·교시·짧은 해시)나 「표준」만 쓴다. 이름이나 발언을 쓰지 않는다. `sources`는 공개 저장소에는 들어가지만 서랍 HTML에서는 빠진다.
- 확인 상태의 `memo`는 화면에 나오지 않지만 공개 저장소에는 들어간다. 선생님 이름이나 발언을 메모에 쓰지 않는다.
- 문서·코드·커밋 메시지에는 「확인 담당 선생님」처럼 역할 이름만 쓴다. 새 코드 파일에 `@author`나 사람 이름을 쓰지 않는다(머리말은 `bsshs-physics-sims contributors`).
- 수업 녹음·전사 파일을 저장소에 복사하지 않는다.

## 외부 통신 금지

- 학교판 빌드는 PhET 통계(yotta 핑, Google Analytics/Tag Manager)를 빈 스크립트로 바꾸고, 새 버전 확인을 끄고, `?yotta` 기본값을 false로 둔다. 공식 PhET 배포본이 아니므로 PhET 통계에 섞이면 안 되고, 학생 기기에서 밖으로 나가는 통신을 만들지 않기 위해서다.
- 글꼴은 시뮬레이션 HTML 안에 data URI로, 목록 사이트에는 같은 사이트의 `fonts/`로 넣는다. 외부 CDN을 쓰지 않는다. 한글은 기기 글꼴로 그린다.
- 새 시뮬레이션 코드와 어댑터에 다른 주소(`http(s)://`)를 넣지 않는다. 서랍은 아무것도 내려받지 않는다.
- 분석 도구, 광고, 추적 픽셀, 외부 폼을 넣지 않는다.
- 확인 방법: `check-sim`이 시뮬레이션을 열어 모든 요청을 기록한다. `file://`로 열면 http(s)/ws 요청이 하나라도 있으면 실패, http(s)로 열면 다른 origin 요청이 있으면 실패다. 배포 뒤에는 실제 주소로 같은 검사를 한다.

## 공개 저장소 정책

- 공개 저장소(`https://github.com/Rayul0325/bsshs-physics-sims`, GPL-3.0)는 이 저장소의 기록과 이어지지 않는 별도 기록이다. 이 저장소에서 `git push`로 공개 저장소에 올리거나, 공개 저장소를 이 저장소의 remote로 두지 않는다.
- 내보내기는 추적 파일만(`git archive HEAD`) 저장소 밖 폴더에 풀어 만든다. gitignore된 것(받은 PhET 소스, `build/`, `dist/`, 로컬 작업 문서, `node_modules`)은 들어가지 않는다. 커밋하지 않은 수정도 들어가지 않는다.
- 공개 저장소 커밋 작성자는 `Rayul0325 <206921773+Rayul0325@users.noreply.github.com>`만 쓴다. 실명이나 개인 메일을 쓰지 않는다.
- 공개 전 검사: 실명·개인 메일·비밀 값·이 컴퓨터의 홈 폴더 절대 경로가 내보낸 파일에 없어야 한다. 빌드 기록 파일의 경로는 빌드 단계에서 `$BSSHS_CACHE`와 `.`로 바뀐다.
- 저장소 이름, 공개 여부를 바꾸거나 새 공개 저장소·배포 프로젝트를 만들기 전에는 관리자에게 확인받는다.

## 자격 증명

- 저장소에는 비밀 값이 하나도 없다. 빌드·검증은 자격 증명이 필요 없다(GitHub `phetsims`는 공개 저장소를 읽기만 한다).
- Cloudflare: `npx wrangler login`(브라우저 대화형)으로 받은 토큰을 wrangler가 사용자 설정 폴더에 둔다. 토큰은 만료되며, 만료되면 배포 명령이 인증 오류를 낸다. 다시 `npx wrangler login`. 토큰을 저장소, `.env`, 문서, 명령 인자에 넣지 않는다. 컴퓨터를 넘기거나 토큰이 샜다고 의심되면 `npx wrangler logout` 뒤 Cloudflare 대시보드에서 해당 API 토큰·세션을 취소한다.
- GitHub: 공개 저장소 push는 관리자 컴퓨터의 git 자격 증명으로 한다. 토큰을 remote 주소에 넣지 않는다(`https://github.com/Rayul0325/bsshs-physics-sims.git` 그대로).
- 배포 때 생기는 `.wrangler/`는 임시 폴더다. 그 안의 파일을 커밋하지 않는다.

## 남는 기록

- `data/verification-status.json`: 상태, 날짜, 승인 당시 해시(누가 언제 무엇을 승인했는지의 근거). 도구로만 쓰고 커밋한다.
- `data/build-matrix*.json`: 시뮬레이션마다 쓴 소스 SHA, 패치·덧대기 결과, 빌드 뒤 체크아웃이 깨끗했는지. 공개 빌드가 어떤 소스에서 나왔는지의 근거다.
- `build/verify/report.json`: 마지막 검증 결과(커밋하지 않음). 배포할 `dist/`가 검증된 것인지 판단하는 근거다.
- 공개 저장소의 커밋 기록, Cloudflare Pages의 배포 목록(되돌리기 기준).
- 학생 기록과 사이트 방문은 어디에도 기록하지 않는다.
