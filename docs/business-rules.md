# 도메인 규칙

## 용어

| 말 | 뜻 |
|---|---|
| 변형 시뮬레이션 | PhET HTML5 물리 시뮬레이션 63개를 고정된 release 브랜치 소스로 다시 빌드한 학교판. 식별은 PhET id + 고정 버전 |
| 새 시뮬레이션 | 직접 설계한 5개: `bsshs-photoelectric`(광전 효과), `bsshs-compton`(콤프턴 산란), `bsshs-laser`(레이저), `bsshs-semiconductor`(반도체·다이오드, 화면 「PN 접합」「정류 회로」), `bsshs-polarization`(편광·브루스터각) |
| 시험 범위 | `data/exam-scope.json`의 `ids`. 지금은 변형 9개 + 새 5개 = 14개, 기준 시험은 2026년 2학기 「전자기와 양자」 기말고사 |
| 수업 서랍 | 시험 범위 시뮬레이션에만 붙는 옆 서랍(좁은 화면에서는 아래 시트). 탭은 「측정 기록」「그래프」「공식·용어」 |
| 측정 항목 | 서랍이 읽는 물리량 하나. `key`, 한국어 이름, 화면 단위, 선택적인 수업 단위 변환을 가진다 |
| 화면 단위 / 수업 단위 | 시뮬레이션이 쓰는 단위(예: nm, eV, G, rpm) / 수업에서 쓰는 단위(대부분 SI, 렌즈는 cm) |
| 모델 값 | 화면에 숫자가 없는 시뮬레이션에서 모델 내부 값을 꺼낸 것. 상대값이면 이름에 「(모델 값)」을 붙인다 |
| 「수업 강조」 | 수업에서 시험에 나온다고 했거나, 외우라고 했거나, 여러 번 반복해 짚은 공식·용어 (`emphasis: true`) |
| 「참고 · 시험 범위 아님」 | 수업에서 시험 범위가 아니라고 분명히 말한 항목에만 붙는 표시 (`outOfScope: true`) |
| 공식의 「참고」 한 줄 | 위 표시와 다른 것이다. PhET 모델과 수업 공식이 근사·규약 때문에 다를 때 그 이유를 공식 칸에 적는 한 줄(`note`) |
| 확인 상태 | 확인 담당 선생님의 검토 결과. `확인 중` · `확인 완료` · `수정 중` |
| 물리 내용 해시 | 시뮬레이션 하나의 물리 내용을 묶어 계산한 sha256. 승인할 때 기록되고, 나중에 다르면 승인이 무효로 보인다 |
| 확인 담당 선생님 | 14개 전부를 확인하는 한 분. 문서·저장소·화면에는 역할 이름만 쓴다 |

## 시뮬레이션 집합

- 변형 63개의 id·release 브랜치·기대 버전은 `data/sims.json` 한 곳에 있다. 각 시뮬레이션은 `phetsims/<id>`의 그 release 브랜치 HEAD를, 형제 저장소는 그 브랜치 `dependencies.json`에 적힌 SHA를 쓴다. PhET 공개 저장소가 2026-10-09에 닫혀서 이 버전들은 지금 PhET 사이트 버전보다 조금 옛것이며, 그 차이는 받아들인 상태다.
- 체크아웃한 `package.json` 버전이 기대 버전과 다르면 빌드를 멈춘다. 고정 버전이 빌드되지 않을 때 다른 버전으로 바꾸지 않는다. 새 버전은 자동으로 따라가지 않고, 필요할 때 사람이 목록을 고쳐 반영한다.
- 새 시뮬레이션은 `sims/` 아래 `_`로 시작하지 않는 폴더다. 지금 5개이고 5개 모두 시험 범위다. `sims/_template`은 공개되지 않는 연습용 틀이다.
- 공개 사이트에 올라가는 수는 63 + 새 시뮬레이션 수(지금 68)여야 한다. 하나라도 빠지면 빌드 검사(V1)가 실패한다.

## 시험 범위 목록

- 시험 범위에 든 시뮬레이션만 서랍, 확인 상태 배지, 목록 카드의 「시험 범위」 표시를 가진다. 지금 시험 범위 밖 시뮬레이션에는 추가 기능이 없다.
- 시험 범위 id 하나에는 다음 네 파일이 모두 있어야 한다: `adapters/<id>/adapter.mjs`, `adapters/<id>/drawer.json`, `adapters/<id>/cases.json`, `data/lessons/<id>.json`. 하나라도 없으면 사이트 빌드(그리고 서랍 주입)가 아무것도 쓰기 전에 실패하고, 모든 시험 범위 id의 빠진 파일을 한꺼번에 출력한다. 서랍 없이, 또는 「공식·용어」 탭이 빈 서랍으로 조용히 공개되는 일은 없다.
- 형식이 틀린 파일(측정 정의, 사례, 연결 코드)도 주입을 멈춘다.
- 새 시뮬레이션은 시험 범위 여부와 상관없이 `sims/`에 폴더가 있으면 공개 대상이다. 시험 범위에서 빠지면 서랍과 배지만 없어지고, 카드는 `data/units.json`의 단원 칸에 남는다.

## 수업 서랍의 동작

- 닫힌 서랍은 실험 화면의 픽셀을 하나도 바꾸지 않는다. 열기 버튼이 차지한 상자만 다르다. 서랍을 열어도 시뮬레이션을 밀거나 다시 배치하지 않고, 위에 덮는다.
- 화면 폭이 토큰의 `breakpoint.sheet`(600px) 이하면 아래 시트, 넘으면 오른쪽 옆 서랍이다. 시트는 선택된 화면의 실험 영역 아래 빈 공간만 덮도록 높이를 정하되 `drawer.sheetMinHeight`(40vh)~`drawer.sheetHeight`(72vh) 안으로 자른다. 폭 `breakpoint.large`(1600px) 이상이면 서랍 본문 글자는 18px 이상이다. 누르는 곳은 가로·세로 44px 이상이다.
- 서랍은 PhET가 화면을 다 만들고 시작 화면이 사라진 뒤에 붙는다. 서랍 안의 조작은 시뮬레이션에 전달되지 않는다.

## 측정 기록

- 기록은 시뮬레이션마다 하나다. 화면(탭)을 바꿔도 같은 표에 쌓이고 「화면」 열로 구분된다. 그 화면에 없는 양은 빈칸이다.
- 줄은 「기록」을 누를 때만 생긴다. 한 줄 = 시각(기기 현지 시각 `YYYY-MM-DD HH:MM:SS`) + 화면 이름 + 모든 측정 항목 값(화면 단위). 수업 단위 변환이 있는 항목은 수업 단위 열이 하나 더 붙는다.
- 어댑터가 숫자가 아니거나 무한대인 값을 주면 그 칸은 빈칸(`null`)이다. 어댑터의 읽기 함수가 예외를 던지면 그 줄의 값이 모두 빈칸이다.
- 유지와 삭제:
  - 새로 고침해도 남는다(브라우저 `localStorage`).
  - 시뮬레이션의 「모두 초기화」를 눌러도 남는다. 학생이 조건을 바꿔 가며 잰 값을 한 표에 모으기 위해서다.
  - 「새 실험 시작」(기록 탭 맨 위, 강조색)을 누르고 확인하면 **그 시뮬레이션의 현재 정의 버전 기록만** 지운다. 다른 시뮬레이션의 기록은 그대로다. 공용 기기에서 앞 반 기록과 섞이지 않게 하는 것이 이 버튼의 몫이다. 지운 기록은 되돌릴 수 없다.
  - 학생이 브라우저 저장소를 지우면 사라진다.
  - 브라우저가 저장소를 막았으면 안내를 띄우고 메모리에만 둔다(페이지를 닫으면 사라짐). 저장 용량이 차서 쓰기에 실패해도 메모리로 이어 쓴다.
- 기록이 기기 밖으로 나가는 길은 CSV와 PNG 내려받기뿐이다. 제출, 로그인, 서버 저장은 없다.

### 측정 정의 버전

- `drawer.json`의 `schemaVersion`(1 이상 정수)이 기록 저장 키에 들어간다: `bsshs:log:<id>:v<schemaVersion>`.
- 배포한 뒤에 측정 항목의 키·뜻·단위를 바꾸면 반드시 `schemaVersion`을 올린다. 올리면 학생이 서랍을 열 때 예전 버전 기록이 있다는 안내가 뜨고, 「이전 기록 CSV 내려받기」 또는 「받지 않고 지우기」를 고른 뒤 예전 기록이 지워진다. 예전 기록과 새 기록을 한 표에 섞지 않는다.
- 올리지 않고 키를 바꾸면 예전 줄이 새 열 이름으로 읽혀 해당 칸이 빈칸이 된다(경고 없음).

## 단위와 PhET 값

- 수업 단위 값 = 화면 단위 값 × `factor` + `offset`. 표·CSV·현재 값에는 두 단위가 함께 나온다. 값 자체는 시뮬레이션이 계산한 것이다.
- 수업 공식과 PhET 값이 다를 때:
  - 단위만 다르면 두 단위로 보여 준다(eV와 J, nm와 m, G와 T, rpm과 rad/s, c와 m/s).
  - 근사·규약 차이면 PhET 값을 그대로 두고 공식 칸에 「참고」 한 줄로 이유를 적는다. 예: 패러데이 법칙 시뮬레이션은 기전력의 + 방향을 반대로 잡아 ε = +N ΔΦ/Δt로 계산한다(크기는 같다). 파동 간섭은 격자 위에서 파동 방정식을 풀어 작은 각 근사 Lλ/d보다 무늬 간격이 5% 이상 크다. 발전기 화면의 rpm 계기는 코일 끌림이 곱해진 값이라 자석의 실제 회전 속력과 따로 보여 준다.
  - PhET의 물리 계산은 어떤 경우에도 고치지 않는다.
- 화면에 숫자가 없는 시뮬레이션은 모델 값을 측정 항목으로 꺼내 기록·검사에 쓴다. 이 값은 서랍 안에만 나오고 실험 화면에는 아무것도 더하지 않는다.

## 그래프

- 시뮬레이션마다 물리적으로 의미 있는 그래프를 2개 이상 미리 정한다. 그래프 축은 화면 단위다. `fit: "linear"`이면 최소제곱 직선을 그리고 기울기·절편·R²를 보여 준다. 서로 다른 x가 2개 미만이면 직선을 그리지 않는다.
- 학생이 x·y 열을 고르는 자유 그래프는 서랍이 자동으로 더하며, 수업 단위 열도 고를 수 있다. 화면별로 줄을 거를 수 있다.
- 화면의 숫자는 유효숫자 4자리, 아주 크거나 작으면 `6.667×10⁻⁴`처럼 쓴다. CSV는 기계가 읽을 수 있는 보통 숫자 표기(`6.667e-7`)다.

## 수업 공식·용어

- 원천의 우선순위: 수업 녹음 기록(과목 이름이 「전자기와 양자」 또는 「물리학」 계열인 기록을 과목으로 골라 씀, 선생님 이름으로 거르지 않음, 2026-08-18 ~ 2026-11-03) → 수업에서 다루지 않은 부분은 표준 물리. 교과서는 쓰지 않는다. 상수는 CODATA 값.
- 선생님 실명과 수업 발언 직접 인용은 넣지 않는다. 표준 문장으로 풀어 쓴다.
- 항목별 원천은 수업 내용 파일의 `sources`에 녹음 식별자(또는 「표준」)로만 적는다. `sources`는 서랍 HTML에 들어가지 않는다. 서랍에 들어가는 필드는 `id`, `title`, `unit`, `formulas`, `terms`, `classUnits`뿐이다.
- 공식의 모든 변수가 상수이거나 측정 항목 키와 같으면, 서랍이 현재 측정값을 수업 단위로 바꿔 대입한 결과를 함께 보여 준다. 그래서 같은 양이면 측정 항목 `key`와 공식 변수 `key`를 같게 쓴다.

## 확인 상태

- 상태는 시험 범위 시뮬레이션마다 `data/verification-status.json`에 `status`, `date`(YYYY-MM-DD), `memo`, 그리고 `확인 완료`일 때만 `approvedHash`(sha256 hex 64자)를 둔다. 항목이 없으면 `확인 중`으로 본다.
- 화면 표시: `확인 중` → 「선생님 확인 중」, `확인 완료` → 「선생님 확인 완료」, `수정 중` → 「수정 중」. `memo`와 선생님 이름은 화면에 나오지 않는다.
- 전이:

| 지금 | 일 | 다음 | 기록 방법 |
|---|---|---|---|
| (새로 공개) | — | `확인 중` | 항목 없음 또는 `set-status … 확인 중` |
| `확인 중` | 선생님이 승인 | `확인 완료` + 그때의 해시 | `npm run approve -- <id> [메모]` |
| `확인 중`, `확인 완료` | 선생님이 오류 지적 | `수정 중` | `npm run set-status -- <id> 수정 중 [메모]` |
| `수정 중` | 고쳐서 다시 공개 | `확인 중` | `npm run set-status -- <id> 확인 중 [메모]` |
| `확인 완료` | 물리 내용 해시가 바뀜 | 화면에 「선생님 확인 중」 | 자동(파일은 `확인 완료` 그대로, 표시만 바뀜) |

- 승인받지 않은 내용이 「확인 완료」를 단 채 보이는 일은 없어야 한다. 상태 표시는 빌드(주입) 때 그 순간의 해시와 비교해 정해지고 HTML에 박힌다. 그래서 상태 파일이나 물리 내용을 바꾼 뒤에는 사이트를 다시 만들어야 화면이 바뀐다.
- `확인 완료`는 승인 도구로만 만든다. 지금 도구는 시작 상태를 가리지 않는다: `approve`는 `수정 중`에서도 바로 `확인 완료`로 쓰고, `set-status`는 어느 상태에서든 `확인 중`·`수정 중`으로 바꾼다. 시험 범위 밖 id는 두 도구 모두 거부한다.
- 상태는 공개 여부와 기능 표시에 영향을 주지 않는다. `수정 중`이어도 서랍 기능은 그대로 보인다.
- 지금 14개 모두 `확인 중`이다(2026-11-04 기록).

### 물리 내용 해시의 범위

- 들어가는 것: `data/lessons/<id>.json`, `adapters/<id>/drawer.json`(측정 항목의 이름·단위·변환, 그래프 정의), `adapters/<id>/cases.json`(물리 검사 사례), `adapters/<id>/adapter.mjs`(학생이 보고 기록하는 값을 읽고 계산하는 코드), 새 시뮬레이션이면 `sims/<id>/js/model/` 아래 모든 파일.
- 빠지는 것(바뀌어도 승인 유지): 디자인 토큰, 테마, 학교 표기, 용어 교정, 서랍 코드, 새 시뮬레이션의 보기(view) 코드.
- 재확인 기준은 「물리 내용이 바뀔 때만」이다. 디자인을 바꿔도 「확인 완료」는 유지된다.
- JSON은 키를 정렬하고 공백을 뺀 형태로 해시한다. 줄 바꿈·들여쓰기만 바꾸면 해시가 그대로이고, 값이 하나라도 바뀌면 달라진다. 없는 파일도 「없음」으로 해시에 들어간다.
- 해시 범위나 계산 방식을 바꾸면 범위 버전(`HASH_SCOPE_VERSION`)을 올린다. 그러면 모든 승인이 「확인 중」으로 돌아간다.

## 공개 조건: 자동 물리 검사

- 서랍 기능이 공개되는 조건은 자동 물리 검사(V3) 통과다. 선생님 확인은 공개 조건이 아니다.
- 검사 사례 하나 = 입력(`params`, 어댑터의 `apply`가 모델을 그 상태로 맞춤) + 기대값(`expect`, 측정 항목 키별). 비교:
  - 기대값이 0이 아니면 상대 오차 `|실제 − 기대| ≤ relTol × |기대|`. `relTol`이 없으면 1%.
  - 기대값이 0이면 절대 오차 `|실제| ≤ 1e-9`. 0이 아닌 작은 값을 기대하면 0 대신 그 값을 적는다.
  - 읽은 값이 `null`이면 실패.
  - 값은 0.1초 간격으로 세 번 연속 같을 때 읽는다(최대 5초). 끝내 안정되지 않으면 마지막 값으로 비교한다.
- 사례에 따로 적은 허용 오차는 이유가 있는 곳만: 파동 간섭 무늬 간격 4%(격자 해상도), 반도체 평활 축전기 리플 6%(근사식 ΔV ≈ V_p/(fRC)와 비교), 그 밖에 정밀 비교용으로 더 좁힌 값(콤프턴·편광).
- 허용 오차를 기본 1%보다 넓힌 측정 항목은 학생에게 그 근사 차이를 설명해야 한다: 수업 내용 파일에 그 측정 키를 변수로 가진 공식이 하나 이상 있고, 그 공식의 `note`가 「참고」로 시작해야 한다. 없으면 그 시뮬레이션의 물리 검사가 실패한다. 지금 해당하는 것은 반도체 `rippleVoltage`(리플 전압 공식)와 파동 간섭 `fringeSpacing`(무늬 간격 공식)이다.
- 새 시뮬레이션은 다음 물리를 모두 사례로 검사한다(문턱 아래 광전자 0개 같은 경계 사례 포함):
  - 광전 효과: K_max = hf − W(금속별 일함수), 문턱 진동수 아래면 광전자 0개, 빛의 세기는 광전류에만 영향, eV₀ = K_max, 광전류-전압 특성.
  - 콤프턴 산란: Δλ = (h / mₑc)(1 − cos θ), 운동량·에너지 보존에 따른 전자 반동.
  - 레이저: 3준위 이상, 펌핑, 자발·유도 방출, 밀도 반전 조건, 유도 방출 광자의 위상·방향이 같음.
  - 반도체: 에너지 띠, n형·p형 도핑, 공핍층, 순·역방향 바이어스 / 반파·브리지 정류, 평활 축전기, 다이오드 모델 세 가지(이상적·고정 전압 강하·구간 선형), 오실로스코프 파형.
  - 편광: I = I₀cos²θ, 편광판 여러 장, 반사에 의한 편광, tan θ_B = n₂/n₁.
- 실패의 처리(물리 검사에 실패한 추가 기능은 공개되지 않는다):
  - **새 시뮬레이션**이 하나라도 사례에 실패하면 물리 자체가 기능이므로 그 시뮬레이션 전체를 공개 사이트에서 뺀다(제외 종류 `sim`). 그러면 공개 수가 68보다 작아져 빌드 검사도 실패한다(조용히 통과하지 않음).
  - **변형 시뮬레이션**이 실패하면 수업 서랍만 빼고, 서랍 없는 일반 학교판으로 공개한다(제외 종류 `drawer`). 시뮬레이션은 계속 공개되므로 공개 수는 그대로지만 물리 검사는 실패로 보고된다. 원인이 어댑터나 사례일 수 있어 사람이 판단한다.
  - 이 제외는 검증 명령 안에서만 적용된다. 전체 빌드 명령이 만든 사이트 폴더는 아직 제외가 적용되지 않은 상태다.
  - 서랍이 빠진 변형 시뮬레이션도 지금은 목록 카드에 확인 상태 배지가 그대로 붙는다.
- 검사는 사례에 적힌 상태만 확인한다. 사례가 덮지 않는 화면·값은 검증되지 않은 것이다.

## 용어 교정

- 한국어 화면 글자에서 **명백한 오역**, **수업 용어와 어긋난 말**, **표기 오류**만 고친다(이유 태그 `오역`·`수업 용어`·`표기`). 문장을 새로 다듬지 않는다. 예: 콘덴서→축전기, 푸우리에→푸리에, 죤 트라볼티지→존 트라볼티지, 파라데이→패러데이, 하전→전하, 「코일 선택」→「검출 코일」(Pickup Coil의 오역).
- 한 시뮬레이션에는 그 시뮬레이션의 `perSim` 목록을 먼저, 이어서 `global` 목록을 파일 순서대로 적용한다. `from`은 한국어 문자열 값 안의 모든 부분 일치를 바꾼다. 키·영어 원문·코드는 바꾸지 않는다.
- `global`에는 어느 시뮬레이션·어느 문자열에서도 안전한 것만 넣는다. 문맥에 따라 다른 것은 `perSim`에 넣고, 번역 파일을 공유하는 시뮬레이션은 각각 적는다.
- 교정은 학교판 빌드에만 적용한다. 새 시뮬레이션은 공통 부품 문자열에 `global`만 적용한다(자기 글자는 처음부터 한국어로 쓴다).
- 영어 키가 없는(빌드에 실리지 않는) 옛 번역 항목은 고치지 않는다.
- 목록 사이트의 변형 63개 제목은 `data/titles.json`이며, 고정 번역 원본 제목에 교정을 적용한 값과 같아야 한다.

## 목록 사이트

- 순서: `data/units.json`의 단원을 `order` 순서로 → 마지막 단원 「기타」. 시험 범위를 따로 묶는 칸은 없다. 시험 범위 시뮬레이션은 자기 단원 칸에만 나오고 「시험 범위」 표시와 확인 배지를 단다.
- 단원 배정은 수업 기록 기준이다. 단원에 속하지 않는 시뮬레이션은 「기타」에 적는다. 68개 모두 정확히 한 단원에 적혀 있어야 한다. 적히지 않은 시뮬레이션은 카드가 생기지 않으므로 목록 사이트 검사가 실패한다.
- 카드: 한국어 제목, 썸네일, 「시험 범위」·「새로 만든 시뮬레이션」 표시, 시험 범위면 확인 배지, 링크. 새 시뮬레이션 제목은 빌드된 HTML의 `<title>`에서 읽는다.
- 바닥: 「부산과학고 학생 제작 · 학교 공식 자료 아님」, PhET 영문 출처 문장, 한국어 원작 표기와 「부산과학고 학생이 수정함」, 라이선스와 「비상업 용도」, 소스 저장소 링크.
